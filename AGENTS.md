# Entrega de cambios

El usuario pidió que, cada vez que se hagan cambios en este proyecto, queden
actualizados tanto el repositorio remoto como la demo pública. Esa instrucción
autoriza el commit, push y despliegue necesarios como parte de la entrega.

- Conservar cambios ajenos y ejecutar las verificaciones apropiadas.
- Publicar los cambios en el remoto del proyecto y actualizar el backend y la
  web pública cuando corresponda; no terminar dejando solo el cambio local.
- Preservar la base y los documentos de la demo. Respaldar antes de migraciones
  y reemplazar únicamente procesos y paquetes propios, comprobando su identidad.
- El frontend público es https://scalaris.com.ar/e-medicapp/ (publicación de origen
  en https://jereprograma.github.io/E-MEDICAPP/) y el backend
  se administra en esta PC. Seguir `docs/github-pages-demo.txt` y los scripts.
- Confirmar el éxito de GitHub Actions y comprobar que `deployment.json.commit`
  corresponda al commit enviado y que `backendUrl` coincida con el servidor
  activo. Que coincida solo la dirección del servidor no acredita la versión.
- Verificar el cambio desde el enlace público. Informar cualquier impedimento
  concreto de publicación sin presentar una entrega local como ya publicada.
