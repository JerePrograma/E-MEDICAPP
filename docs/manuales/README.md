## Por dónde empezar

1. Ingresá como **Administrador de plataforma** y revisá **Administración**. La sucursal de ejemplo todavía está pendiente de verificación y adhesión; el catálogo y el stock empiezan vacíos. Para una presentación, documentá condiciones ficticias; para operación real, comprobá las condiciones reales.
2. Seguí su manual para completar la sucursal, registrar productos y definir el esquema de suscripción o habilitación que corresponda.
3. Ingresá como **Operador** o **Farmacéutico** y cargá las existencias y precios de esa sucursal.
4. Ingresá como **Comprador** y creá la solicitud. Usá los manuales de comprador y farmacéutico para la revisión y la aceptación del presupuesto.
5. Continuá con el operador para pago, factura y preparación; con el farmacéutico para dispensación; y con el cadete para entrega. El retiro se confirma desde farmacia por un farmacéutico.
6. Consultá el manual de **Administrador de farmacia** para mantener la sucursal y su equipo.

En esta presentación usá personas, documentos y operaciones ficticias. La aplicación registra los pagos y reintegros comprobados; no ejecuta transferencias. Estas cuentas están en la base pública de operación, separadas del entorno DEMO local. Crear las cuentas no cambia el modo de la aplicación ni carga compras o cobros.

## Incorporar personas y farmacias reales

Consultá [Alta real de cuentas y farmacias](07-alta-real-de-cuentas-y-farmacias.md).

Cada persona se registra y confirma su correo. Luego la administración asigna la función y las sucursales correspondientes. Una sucursal es un establecimiento, no una cuenta con contraseña propia.

El envío de correo está preparado pero pendiente de configuración. Las cuentas temporales ya tienen el acceso habilitado expresamente; los registros nuevos necesitan la confirmación normal. No se borró ni reinicializó la base existente.
